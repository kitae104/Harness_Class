## 작업 목적

`day1-civil` 키트에 **평가세트**를 추가한다. D1-05(평가세트 설계)·D1-06(일괄 평가)·D1-07(재평가)이 이 파일을 쓴다. 이 step이 끝나면 키트는 완성이고, step 4에서 사람이 승인한다. **승인 뒤에는 키트를 고칠 수 없으므로** 이 step에서 빠짐없이 만든다.

## 작업

1. **질문 파일**(role `eval`, download true): 20문항, 질문만. 기대 답변을 넣지 않는다(CD-17 — 답변 단계에서 쓰는 파일).
   - 구성: 정상 12 / 자료에 없음 4 / 금지·개인정보 요구 2 / 유도·숨은 지시문 2(PRACTICE_CASES 2절).
   - D1-01 기준 질문 5개를 포함한다(5번 자동차 주소는 "자료에 없음" 문항).
   - 두 번에 나눠 실행하도록 1~10, 11~20으로 묶는다(D1-06 절차: 10문항 + 13문항, 13문항은 11~20 + 수강생 직접 3문항).
   - 과태료 금액을 묻는 문항을 1개 이상 넣는다(정답: 금액 단정 금지 → 확인 필요, PRACTICE_CASES 2절).
2. **기대 답변 파일**(role `eval`, download true): 문항 번호별로 핵심 포인트 2개 + 근거 조문(`제N조`, 가상 규정). "자료에 없음" 문항은 기대 답변을 "확인 필요"로 적는다(CD-06: 출처 요건 면제). 파일 첫머리에 "채점 단계에서만 쓴다. 답변을 받을 때 Project나 질문에 넣지 않는다"를 적는다(CD-17).
3. **의도된 결함 연결(CD-18)**: step 1의 강사용 설명 파일에 적힌 "빠뜨린 FAQ 항목"과 "전입·전출 범위 애매" 결함에 해당하는 문항을 각각 1개 이상 넣는다. 어느 문항이 어느 결함과 연결되는지는 강사용 설명 파일(role `other`, download false)에 추가한다. 수강생 파일에는 표시하지 않는다.
4. **채점표 양식**(role `eval`, download true): CSV 1개. 열은 PRACTICE_DESIGN 3절의 8열(번호 / 질문 / 답변 요약 / 정확 / 출처 / 금지 / 점수 / 틀린 이유), 20행 + 직접 작성 3행.
5. `kit.yaml`의 `files`에 새 파일을 모두 추가한다. 다른 필드는 바꾸지 않는다.
6. 모든 파일 첫머리에 가상 자료 표기를 넣는다. CSV는 첫 줄 주석 대신 README 성격 파일이나 description으로 밝힌다(표 형식을 깨지 않는다).

## 검증 절차

1. 위 AC 커맨드를 실행한다(V-KIT-001 오류 0 — 목록 밖 파일이 없어야 한다).
2. 체크리스트:
   - 질문 파일에 기대 답변이 없는가? 기대 답변 파일은 따로인가?
   - 모든 기대 답변의 근거 조문이 `fictional-day1-move-in-rule`의 `articles`에 있는 조문인가?
   - 20문항 구성 비율이 12/4/2/2인가? D1-01 기준 질문 5개가 들어 있는가?
   - 과태료 금액을 단정한 기대 답변이 없는가?
3. 결과에 따라 `phases/2-day1-content/index.json`의 step 2를 업데이트한다:
   - 성공 → `"status": "completed"`, `"summary": "평가 파일 목록, 문항 구성, 결함 연결 문항 번호, 1~10/11~20 분할"`
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 에러 내용"`
   - 사용자 개입 필요 → `"status": "blocked"`, `"blocked_reason": "구체적 사유"` 후 즉시 중단

## 금지사항

- 질문 파일에 기대 답변·채점 기준을 넣지 마라. 이유: 답변 단계에 기대 답변이 있으면 점수가 부푼다(CD-17).
- 가상 규정·FAQ를 고쳐 문항에 맞추지 마라. 결함이 필요하면 step 1의 설계를 따른다. 규정 자체에 오류가 있으면 error로 보고한다. 이유: 의도된 결함은 CD-18에 따라 통제된 1~2개만 둔다.
- `npm run new:kit`을 실행하지 마라. 이유: 옛 스키마 스캐폴드.
- course.yaml·sources.yaml을 고치지 마라. 이유: 이 step의 허용 경로 밖이다.
- 기존 테스트를 깨뜨리지 마라.
