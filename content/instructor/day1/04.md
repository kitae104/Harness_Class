# 강사 안내 — Day 1 · 4교시 근거 자료 연결과 출처 답변

공개 가능한 진행 안내만 적는다(CD-02). 활동별 시간은 course.yaml `d1-context`의 activities를 따른다.

## 준비
- 강사 화면에 D1-3에서 만든 Project v1(자료를 올리기 전)을 열어 둔다. 시연 1단계에서 출처 없는 답을 받는다.
- 키트 zip을 미리 내려받아 압축을 풀어 둔다. 업로드가 막힌 수강생에게 본문 붙여 넣기를 보여 줄 때 쓴다.

## 시연 순서
1. D1-1 체험 질문을 다시 띄우고 "오늘 이 질문을 근거 자료로 확인한다"고 말한다. 개념(근거·출처·기준일)은 한 줄씩만 말하고 넘어간다.
2. Project v1에 체험 질문을 묻는다. 답에 출처가 있는지 수강생에게 묻는다.
3. 키트를 내려받기 전에 페이지의 "교육용 가상 규정" 안내 박스를 소리 내어 읽는다. 실제 법령 원문이 아니고 실습용으로 만든 자료이며, 실제 업무에서는 실제 법령을 확인한다는 것을 꼭 말한다.
4. 규정 파일과 FAQ 파일을 Project 파일로 올리는 과정을 보여 준다. 나머지 키트 파일은 올리지 않는다고 짚는다.
5. 카드의 출처 규칙을 **지침란**에 붙여 넣고 대괄호를 바꾸는 것까지 보여 준다. 채팅창에 붙이지 않는다는 것을 강조한다(막힘 지점 sp-d1-04-a).
6. 같은 체험 질문을 새 대화에서 다시 묻고, 비교 체크리스트 세 항목(근거·범위·단정)을 짚는다.
7. 답에 나온 조문 번호를 규정 파일에서 직접 찾아 보여 준다. 수강생도 실습에서 같은 동작을 한다(막힘 지점 sp-d1-04-b).

## 실습 진행
- 질문 하나에 2분 정도 걸린다. 다섯 개를 한 번에 붙이지 않고 하나씩 묻게 한다. 조문을 찾아보는 시간이 필요하다.
- 조문 번호가 나오면 반드시 규정 파일을 열어 찾게 한다. 체크는 찾은 뒤에만 한다.
- 먼저 끝난 수강생은 접이식 "잘못된 결과 예시"를 열어 지어낸 조문을 알아보는 세 가지 확인을 읽게 한다.
- 자료 목록은 한 자료에 한 줄, 네 칸만 적는다. 기준일은 오늘 날짜다(막힘 지점 sp-d1-04-d).

## 흔한 오류
| 증상 | 대응 |
|---|---|
| 파일은 올렸는데 답에 조문 번호가 없다 | 지침란에 출처 규칙이 저장되었는지 확인하게 한다. 저장 뒤 새 대화에서 다시 묻게 한다 |
| 출처 규칙을 채팅창에 붙여 넣었다 | 지침란으로 옮기게 한다. 채팅에 붙인 규칙은 그 대화에만 적용된다고 설명한다 |
| 대괄호를 바꾸지 않고 저장했다 | 대괄호 부분을 자료 이름과 담당 연락처로 바꾸게 한다 |
| 파일 업로드가 막힌다(교육망, 사용량 한도) | 페이지 "잘 안 될 때"의 대안으로 본문을 붙여 넣게 한다. 자료 목록의 "올린 곳"에 "본문 붙여 넣기"라고 적게 한다(막힘 지점 sp-d1-04-c) |
| 답의 조문 번호를 그대로 믿는다 | 규정 파일에서 그 조문을 찾아 제목과 내용이 맞는지 보게 한다 |
| 자료 밖 질문에 그럴듯한 답이 나온다 | 출처 규칙의 "모를 때" 줄이 지침에 있는지 보게 한다. 그래도 나오면 이 사례를 D1-7 실패 분석 때 다시 쓰도록 메모하게 한다 |
| "실제 법령도 이렇게 되어 있나요?"라고 묻는다 | 이 규정은 실습용 가상 규정이라 실제와 다를 수 있다고 답한다. 실제 업무에서는 페이지에 표시된 실제 법령을 확인하게 한다 |
| 과태료 금액을 묻는다 | 가상 규정은 금액을 정하지 않는다. 금액을 짐작해 말하지 않는 것이 이 비서의 규칙이라고 설명한다 |

## 시간이 부족할 때 생략
course.yaml `skip_if_short`와 같다.
- 파일 형식 비교(본문 접이식 "더 해보기")는 건너뛴다.
- 그래도 부족하면 시연 6·7단계를 합쳐 한 번만 보여 준다. 수강생 실습의 다섯 질문과 자료 목록 기록은 줄이지 않는다. 세 학습목표를 확인하는 활동이다.

## 다음 교시로 넘길 것
