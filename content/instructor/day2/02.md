# 강사 안내 — Day 2 · 2교시 여러 건 분류·요약

공개 가능한 진행 안내만 적는다(CD-02). 활동별 시간은 course.yaml `d2-batch-classify`의 activities를 따른다. 기대 분류표와 개인정보 행은 키트 `day2-civil-intake`의 강사용 설명(`instructor-notes.md`) 2~4절이 원천이다.

## 준비
- 강사 화면에 민원 답변 비서 Project v3를 열어 둔다. Project 파일 목록에 규정·FAQ(보충본)만 있는 상태에서 시작한다.
- 오늘 쓸 표를 정한다. 공용 폼 응답이 충분하면 응답 시트를 표 파일(CSV)로 내려받아 나눠 주고, 모자라면 제공 `civil-requests-30.csv`를 쓴다. 예상 결과와 기대 분류표는 제공 CSV 기준이다.
- 시연용 "-점검" 표 파일을 미리 만들어 둔다. 개인정보가 든 행(키트 강사용 설명 2절)을 `[개인정보 삭제]`로 바꾼 것이다.
- 개인정보가 든 행의 번호는 이 안내와 수강생 페이지에 쓰지 않았다. 찾는 활동이므로 수업 중 먼저 알리지 않는다. 다른 사람의 정보가 든 행이 하나 있다.

## 시연 순서
1. 첨부 전 개인정보 점검을 먼저 한다. 복사본을 만들고 메모장으로 여는 것까지 보여 준 뒤, 수강생이 스스로 찾게 한다. 5분이 지나면 짝과 찾은 건수를 비교하게 한다.
2. D2-1의 응답 시트를 표 파일(CSV)로 내려받는 곳을 보여 준다.
3. 분류 기준표를 Project 파일로 올린다. "기준표는 근거, 민원 표는 입력"이라고 말하며 페이지의 두 줄 표를 짚는다(막힘 지점 sp-d2-02-a).
4. Project 새 대화에 "-점검" 파일을 첨부하고 카드를 붙인다. 대괄호 세 곳을 바꾸는 것까지 보여 준다.
5. 보낸 뒤 Project 파일 목록을 다시 열어 표 파일이 들어갔는지 함께 본다. 들어갔으면 지운다. 이 동작은 아직 확인 전이다 [TBD: OQ-05].
6. 결과 표의 행 수를 세고, 표 아래 "확인 필요 N건"과 표의 "예" 개수를 직접 비교해 보인다.

## 실습 진행
- 분류는 한 번만 실행한다. 30건 결과를 기다리는 동안 분류 기준표 3절을 미리 읽게 한다.
- 확인 필요 건수와 이유는 페이지의 "예상 결과"와 키트 강사용 설명 3절에 있다. 검토를 마치기 전에는 예상 결과를 열지 않게 한다. AI가 건수를 다르게 내면 어느 건이 다른지 기준표 3절로 짚게 한다. 답을 바로 알려 주지 않는다.
- 개인정보 3건을 확인 필요로 넣은 수강생에게는 "개인정보는 비고로, 확인 필요는 A~E로" 구분하게 한다.
- "요즘 너무 힘듭니다" 한 줄 민원은 위기일 수 있어 사람이 먼저 연락해야 하는 건이라는 점을 꼭 말한다. AI가 단순 문의로 줄이는 것이 이 교시의 대표 잘못된 결과다.
- 긴급도는 경계 사례에서 한 칸 차이가 날 수 있다(예: 공사 소음). 틀렸다고 단정하지 않고 "기준표 어느 줄로 판단했나"를 묻게 한다.
- 분류 대장은 하네스 대장에 "분류 대장" 탭을 만들어 붙인다. 표가 깨지면 "표가 깨질 때" 카드를 쓰게 한다(막힘 지점 sp-d2-02-b).
- 분류 대장 붙이기와 "카드를 지침으로 옮기기"는 합쳐 8분 안에 한다. 옮기기는 지침 버전 기록 → 분류 규칙 붙이기 → 개정 기록 한 줄 순서다. 짧은 요청으로 다시 해 보는 것은 D2-3 시작에서 한다(막힘 지점 sp-d2-02-c).
- "긴 요청을 매번 붙이는 것은 하네스가 아니다. 반복 규칙은 지침에, 기준은 근거에 둔다"를 한 문장으로 정리해 준다. 기준표의 내용(부서·긴급도 기준)을 지침에 옮겨 적지 않게 한다.

## 흔한 오류
| 증상 | 대응 |
|---|---|
| 민원 표 파일을 Project 파일로 올렸다 | Project 파일 목록에서 지우고 새 대화에 첨부해 다시 분류하게 한다. 근거와 입력이 섞이면 다음 대화에서 민원 내용을 근거처럼 쓸 수 있다고 설명한다 |
| 개인정보를 지우지 않은 원본을 첨부했다 | 그 대화를 지우게 한다. "-점검" 파일로 새 대화에서 다시 하게 한다. 결과 표에 옮겨졌는지도 확인하게 한다 |
| 다른 사람의 이름·주소가 든 행을 놓쳤다 | "다른 사람의 정보도 개인정보"라고 짚고 다시 찾게 한다(막힘 지점 sp-d2-02-d) |
| 메모장에서 글자가 깨져 보인다 | 구글 시트로 열어 지우고 다시 표 파일로 내려받게 한다 |
| 따옴표나 쉼표까지 지워 표가 어긋났다 | 원본을 다시 복사해 이름·주소 부분만 바꾸게 한다 |
| 표 아래 확인 필요 건수를 그대로 적었다 | 표의 "예"를 직접 세게 한다. 대장에는 직접 센 수를 적는다 |
| 결과가 중간에 끊긴다 | "출력이 끊기거나 너무 길 때" 카드를 끊긴 대화에 붙이게 한다. 두 번 이상 끊기면 15건씩 나눠 새 대화에서 분류하게 한다 |
| 표를 시트에 붙이면 한 칸에 모인다 | "표가 깨질 때" 카드를 그 대화에 붙이게 한다. 다시 받은 표의 행 수를 확인하게 한다 |
| 첨부가 막힌다(교육망, 사용량 한도) | 페이지 "잘 안 될 때"의 플랜 B로 "-점검" 파일 내용을 붙여 넣게 한다. 카드 문장의 "첨부한 표 파일"을 "붙여 넣은 표"로 바꾸게 한다 |
| 분류 규칙을 채팅창에 붙였다 | 지침란으로 옮기게 한다. 채팅에 붙인 규칙은 그 대화에만 적용된다 |
| 기준표의 부서·긴급도 기준까지 지침에 옮겨 적었다 | 기준 내용은 기준표에만 둔다. 지침에는 "어떻게 분류할지"만 둔다고 설명한다 |

## 시간이 부족할 때 생략
course.yaml `skip_if_short`와 같다.
- "더 해보기"(우선순위 규칙 추가)는 건너뛴다.
- 그래도 부족하면 확인 필요 검토를 "예"인 건의 이유 기호 대조만 하게 한다. 개인정보 점검, 첨부와 파일 목록 확인, 분류 대장의 확인 필요 건수는 줄이지 않는다. 두 학습목표를 확인하는 활동이다.

## 다음 교시로 넘길 것
- 분류 대장에 결과 표와 직접 센 확인 필요 건수가 있는지 확인한다. D2-3에서 이 대장의 건을 골라 초안을 만들고 대장 번호로 검토를 기록한다.
- 지침란에 "여러 건 분류 규칙"이 저장되었는지, 옮기기 전 지침이 지침 버전에 있는지 확인한다. D2-3 시작에서 짧은 요청으로 같은 결과가 나오는지 본다.
- Project 파일 목록에 규정·FAQ·분류 기준표만 있고 민원 표 파일이 없는지 확인한다.

## 강의 준비
- 강의실 PC(교육망)에서 Project 채팅에 CSV를 첨부해 분류가 되는지, 첨부한 파일이 Project 파일 목록에 들어가는지 확인한다 [TBD: OQ-05]. 결과에 따라 시연 순서 5와 페이지의 파일 목록 확인 단계를 고친다. xlsx 첨부도 함께 확인한다.
- 공용 폼 응답을 수업 중 표 파일(CSV)로 나눠 줄 방법(공유 폴더 등)을 정한다. 응답 시트는 강사만 본다(prep/google-sheets-forms.md 4절).
- 카드 `card-classify-attachment`, `card-help-broken-table`을 실제로 테스트하고 `tested_at`·`tested_by`를 채운다(prep/card-tests.md Day 2 카드). 표가 깨질 때 카드는 탭 구분 표를 시트에 붙였을 때 칸이 나뉘는지 실제 화면으로 확인한다.
- 제공 CSV를 메모장과 구글 시트로 열었을 때 한글이 깨지지 않는지 강의실 PC에서 확인한다.
