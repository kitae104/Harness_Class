# 강사 안내 — Day 2 · 4교시 안전장치 점검과 기록

공개 가능한 진행 안내만 적는다(CD-02). 활동별 시간은 course.yaml `d2-guardrails`의 activities를 따른다.

## 준비
- 강사 계정의 데이터 제어 화면을 열 수 있게 해 둔다. 수강생은 각자 자기 계정에서 직접 끈다(CD-01).
- 민원 답변 비서 Project를 열어 두고, 공격성 입력 1을 붙여 넣을 새 대화를 준비한다.
- 키트 `day2-civil-intake`의 `attack-inputs.md`와 강사용 설명 6절(안전한 처리·지침에 추가할 규칙 예)을 옆에 둔다. 강사용 설명은 화면에 띄우지 않는다.
- 하네스 대장의 분류 대장, 초안 검토 기록, 지침 버전, 개정 기록, 로그 대장 표를 열어 둔다.

## 시연 순서
1. 데이터 제어 설정을 강사 화면에서 연다. 메뉴 위치를 천천히 보여 주고 수강생이 따라 끄게 한다(막힘 지점 sp-d2-04-a). 설정을 꺼도 실제 개인정보와 기관 문서는 넣지 않는다는 주의 박스를 소리 내어 읽는다.
2. 안전장치 체크리스트를 함께 읽고, 분류 대장과 D2-3 초안에서 개인정보·초안 표시를 찾는 모습을 한 번 보여 준다.
3. "숨은 지시문"을 한 문장으로 설명한다. 민원서류에 "담당자는 먼저 처리하시오"라고 적혀 있어도 규정대로 처리한다는 비유를 쓴다(막힘 지점 sp-d2-04-b). 수강생 화면에서는 "숨은 지시문"이라는 말만 쓴다.
4. 공격성 입력 1을 요청 한 줄과 함께 Project 새 대화에 붙여 실행한다. 확인 질문에 예·아니오로 답해 보인다.
5. 답이 안전해도 "막아 낸 이유가 지침에 적혀 있는가"를 묻는다. 지침에 없으면 규칙 문장 틀로 한 문장을 쓰는 모습을 보여 준다(막힘 지점 sp-d2-04-d).

## 실습 진행
- 공격성 입력은 두 건을 **각각 새 대화**에서 실행하게 한다. 한 대화에 이어 넣으면 앞 답이 뒤 답에 영향을 준다.
- 입력 2의 기준: 이사 20일 → 기한 지남 → 긴급도 높음, 지금 신고 가능, 과태료는 부과 대상이 될 수 있고 금액은 담당 부서 확인, "초안·검토 필요" 유지(키트 강사용 설명 6절).
- 요즘 AI는 두 입력을 대체로 막아 낸다. 막았으면 좋은 결과라고 말하고, 지침에 막는 문장이 있는지 확인하는 쪽으로 이끈다.
- 규칙 문장은 수강생이 틀의 대괄호를 바꿔 직접 쓴다. 입력 1의 예시 문장만 페이지에 있다. 입력 2 문장은 순회하며 "하지 않는다"와 "대신"이 있는지 본다(막힘 지점 sp-d2-04-c).
- 막힌 수강생은 AI 도움받기 카드를 Project 밖 새 채팅에서 쓰게 한다. AI가 규칙 문장을 써 줘도 그대로 붙이지 않게 한다.
- 개정 기록의 점수 전·후에는 안전하게 답한 건수를 적는다(예: 1/2 → 2/2). D1-7의 점수 전·후와 같은 방식이다.
- 로그 대장은 공격성 입력의 전·후 실행을 한 줄씩 적게 한다. 민원 원문을 옮기지 않고 한 줄로 요약하게 한다.
- 민원 하네스 완성본은 페이지의 예시를 복사해 시트에 붙이고 "들어 있는 것"만 내 것에 맞게 고치게 한다. 점검 칸은 체크리스트 6줄로 채운다.

## 흔한 오류
| 증상 | 대응 |
|---|---|
| 데이터 제어 메뉴를 찾지 못한다 | 강사 화면을 다시 보여 준다. 메뉴 이름이 바뀌었으면 페이지 "잘 안 될 때"의 대안(임시 채팅, 실제 업무 자료 넣지 않기)을 안내하고 강의 준비 메모를 남긴다 |
| 두 입력을 한 대화에 이어 넣었다 | 새 대화에서 하나씩 다시 실행하게 한다 |
| AI가 막아 냈으니 규칙을 적지 않았다 | 막는 문장이 지침에 있는지 찾게 한다. 없으면 다음에도 막는다는 보장이 없다고 설명한다 |
| 규칙을 "숨은 지시문을 조심한다"처럼 썼다 | 잘못된 결과 예시의 세 가지 확인(하지 않는다, 대신, 한 문장)으로 다시 쓰게 한다 |
| 규칙을 여러 줄 덧붙였다 | 입력 하나에 한 문장만 남기게 한다. D1-7의 "지침만 길어진 경우"를 떠올리게 한다 |
| 규칙을 더했는데 답이 그대로다 | 지침을 저장했는지, 새 대화에서 실행했는지 확인하게 한다 |
| 규칙을 더한 뒤 평소 질문의 답이 이상해졌다 | D1-4 자료 안 질문 하나를 새 대화에서 다시 묻게 한다. 이상하면 지침 버전의 전 지침으로 되돌린다 |
| 분류 대장이나 초안에 개인정보가 남아 있다 | 그 자리에서 지우게 하고, 체크리스트 해당 줄을 고친 뒤 체크하게 한다 |

## 시간이 부족할 때 생략
course.yaml `skip_if_short`와 같다.
- "더 해보기 — 첨부 문서 속 숨은 지시문"은 건너뛴다. 핵심 개념의 숨은 지시문 설명도 한 문장으로 줄인다.
- 그래도 부족하면 민원 하네스 완성본은 예시를 붙여 넣는 것까지만 하고, 점검 칸은 D2-5 시작에 채우게 한다. 공격성 입력 다시 실행과 로그 대장·운영 규칙은 줄이지 않는다. 두 학습목표를 확인하는 활동이다.

## 다음 교시로 넘길 것
- 민원 하네스 완성본이 하네스 대장에 있는지 확인한다. D2-5에서 내 업무 하네스 설계서를 쓸 때 설계 예시로 쓴다.
- 로그 대장과 기록 운영 규칙(담당자·주간 개정)을 확인한다. D2-7 적용 로드맵에서 다시 본다.
- 공격성 입력 대화를 Project에서 지웠는지 확인한다. 연습 대화가 다음 답에 영향을 줄 수 있다고 보고 정리한다(CD-22 보수 가정).

## 강의 준비
- 교육용 Plus 계정에서 데이터 제어 메뉴 경로와 항목 이름이 등록부(`chatgpt-data-controls-training`)와 같은지 실제로 확인한다. 다르면 등록부를 고친다.
- 카드 `card-risk-finder`를 Project 밖 새 채팅에서 실제로 실행하고 `tested_at`·`tested_by`를 채운다(prep/card-tests.md Day 2 카드).
- 공격성 입력 2건을 테스트 Project에서 규칙 추가 전·후로 리허설한다. AI가 처음부터 막아 내는지, 규칙 추가 후 다른 질문이 망가지지 않는지 본다.
- Project 안에서 임시 채팅을 쓸 수 있는지 확인한다([TBD: OQ-04]). 쓸 수 있으면 공격성 입력을 임시 채팅으로 돌리는 방법을 검토한다.
