# 강사 안내 — Day 2 · 5교시 내 업무 하네스 설계

공개 가능한 진행 안내만 적는다(CD-02). 활동별 시간은 course.yaml `d2-project-design`의 activities를 따른다. 프로젝트형 교시라 강사 시연은 최소로 하고, 수강생이 스스로 쓰는 동안 순회하며 돕는다. 예시별 평가 문항이 확인하는 것은 각 키트의 강사용 설명(`content/kits/<id>/instructor-notes.md`)이 원천이다.

## 준비
- 강사 화면에 D2-4에서 정리한 민원 하네스 완성본(하네스 대장 "민원 하네스 완성본" 표)과 `/templates/`의 설계서 양식을 나란히 열어 둔다.
- 예시 5종 키트 zip을 모두 내려받아 두고, 키트마다 지침서 틀과 평가 질문 파일을 한 번씩 열어 본다. 순회 중 "이 칸에 무엇을 쓰나요"에 바로 답하기 위해서다.
- 수강생이 설계서를 쓸 곳(메모장 또는 개인 구글 문서)을 미리 정해 알린다. 설계서는 D2-6·D2-7에서 계속 고친다.

## 도입 (시연 대신 짧게)
1. 민원 하네스 완성본을 띄우고 "오늘은 같은 6칸을 다른 업무로 채운다"고 말한다. 새로 배우는 것이 없다는 점을 강조한다.
2. 예시 5종 표를 짚고 "흐름이 닮은 것, 반복이 많은 것, 모르겠으면 민원 답변 초안"을 한 번 말한다. 고르는 데 5분을 넘기지 않게 한다.
3. "실제 업무 자료는 넣지 않는다, 실무 적용은 기관 보안 협의 뒤"를 소리 내어 말한다(CD-01).

## 순회 지도
- **예시 선택(5분)**: 고르지 못하는 수강생에게는 민원 답변 초안 비서를 권한다. 내 업무가 예시와 전혀 다르면 가장 가까운 예시로 하고, 내 업무는 설계서 옆에 메모만 하게 한다.
- **설계서(15분)**: 순서(머리 칸 → ① → ② → ⑤ → ③ → ④·⑥)대로 쓰는지 본다. 한 칸에 오래 머무는 수강생에게 설계 예시 표의 "묻는 질문"을 읽어 주고 답하게 한다(막힘 지점 sp-d2-05-a).
- **③ 도구 칸**: "ChatGPT"라고만 쓴 수강생이 가장 많다. "입력은 어디서 들어오고 결과는 어디에 쌓이나요?"를 묻는다. 회의록처럼 폼이 없는 업무는 지금 쓰는 흐름을 적게 한다(CD-09).
- **카드**: 업무 설명을 먼저 3~5문장으로 직접 쓰게 한 뒤에 카드를 쓰게 한다. 빈 설명으로 카드를 쓰면 AI가 설계서를 대신 쓰기 쉽다(막힘 지점 sp-d2-05-b).
- **점검표**: 7·8번은 평가 실습 뒤, 현재 점수는 D2-6에서 채운다고 알려 준다. "아니오" 항목을 하나라도 고치게 한다.
- **평가 10문항(10분)**: 바꾼 문항의 기대 답변을 고쳤는지 본다. 질문만 바꾸고 기대 답변은 키트 그대로인 경우가 흔하다(막힘 지점 sp-d2-05-c). 근거를 키트 파일에서 직접 찾게 한다.
- 먼저 끝난 수강생은 접이식 "잘못된 결과 예시"로 짝의 설계서를 한 번 봐 주게 한다.

## 흔한 오류
| 증상 | 대응 |
|---|---|
| 칸마다 "친절하게", "주의한다" 같은 형용사만 있다 | "이 문장으로 AI가 무엇을 하거나 하지 않나요?"를 묻는다. 확인할 수 있는 문장으로 바꾸게 한다 |
| ② 근거 칸에 "관련 자료"라고만 썼다 | 키트의 규정·양식 파일 이름을 그대로 적게 한다. 다음 시간에 올릴 파일이다 |
| 입력 자료(CSV·회의 메모)를 ② 근거 칸에 적었다 | 근거는 Project 파일, 입력은 채팅 첨부라고 D2-2의 구분을 다시 짚는다. 입력은 ③ 도구 칸에 적게 한다 |
| 지침 칸에 기한·금액 같은 사실을 적었다 | 사실은 근거 파일에 있다고 말하고, 지침 칸에는 행동 규칙만 두게 한다 |
| 평가 문항을 모두 "정상" 유형으로 바꿨다 | 네 유형(정상, 자료에 없음, 금지·개인정보 요구, 유도·숨은 지시문)이 남도록 되돌리게 한다 |
| 질문만 바꾸고 기대 답변은 키트 것 그대로 두었다 | 기대 답변 복사본의 같은 번호를 고치게 한다. 답을 모르겠으면 그 문항은 원래 후보로 되돌린다 |
| 기대 답변 파일을 어디에 올리냐고 묻는다 | 어디에도 올리지 않는다. 채점할 때만 Project 밖에서 연다(CD-17) |
| AI가 써 준 설계서를 그대로 붙였다 | 카드의 "내가 답할 질문"에 스스로 답해 다시 쓰게 한다. AI가 예로 든 조문·기한은 지우게 한다 |
| 실제 소속 기관 자료를 넣으려 한다 | 막는다. 가상 자료로만 실습하고, 실제 자료는 로드맵의 보안 협의 뒤라고 말한다 |

## 시간이 부족할 때 생략
course.yaml `skip_if_short`와 같다.
- 평가 문항을 5개(키트 1~5번)로 줄인다. 바꿔 쓰기도 1문항으로 줄여도 된다. D2-6에서 실행하는 문항이라 5개는 반드시 정한다.
- 카드와 "잘못된 결과 예시"는 막힌 수강생만 쓴다. 설계서 6칸 작성과 점검표 자기 점검은 줄이지 않는다. 첫째 학습목표를 확인하는 활동이다.

## 다음 교시로 넘길 것
- 모든 수강생이 설계서 v1 파일과 "-내것" 평가 질문·기대 답변 파일을 가지고 있는지 확인한다.
- 평가 표 "질문" 칸에 최소 1~5번이 적혀 있는지 본다. D2-6에서 이 문항으로 첫 점수를 잰다.
- 고른 예시별 인원을 세어 둔다. D2-6 순회 때 입력 자료가 있는 예시(현장 점검, 수요조사, 회의록)를 먼저 돌아본다.

## 강의 준비
- 카드 `card-work-analysis`를 실제로 테스트하고 `tested_at`·`tested_by`를 채운다(prep/card-tests.md Day 2 카드 표). 설계서를 대신 써 주지 않는지, 조문·기한을 지어내지 않는지 본다.
- 예시 키트 5종을 각각 한 번씩 미리 돌려 본다. 강사용 Project를 키트마다 만들어 근거 파일을 올리고 1~5번 답을 받아 두면 D2-6 순회에서 예상 답과 비교할 수 있다(각 키트 `instructor-notes.md` 강의 준비).
- `/templates/`의 설계서 양식 복사 버튼과 인쇄 모양(A4 한 장)을 강의실 PC에서 확인한다.
