# 강사 안내 — Day 2 · 7교시 개선·상호평가·적용 로드맵

공개 가능한 진행 안내만 적는다(CD-02). 활동별 시간은 course.yaml `d2-wrapup`의 activities를 따른다. 프로젝트형 교시라 강사 시연은 두지 않고 순회 지도와 진행 관리에 집중한다. 실패 원인 3분류는 D1-07, 재평가는 D2-06(= D1-06)과 같다.

## 준비
- 강사 화면에 D1-07 페이지의 "실패 원인 3분류"와 `/templates/`의 점검표 12항목을 열어 둔다.
- 상호평가 폼 링크(준비됐다면)를 나눌 수 있게 둔다. 준비 전이면 `/templates/` 점검표를 인쇄해 수강생 수만큼 준비한다.
- 수료 설문 링크(또는 QR)를 준비한다. 운영 기관의 공식 설문이 있으면 그것을 쓴다.
- 발표자 두세 명을 개선 실습 중에 미리 정해 둔다. 점수가 오른 사람, 원인을 잘못 짚었다가 바로잡은 사람, 로드맵이 구체적인 사람을 고르면 좋다.

## 진행 순서와 시간 관리
1. 개선과 재평가(12분): 시작하며 "한 문항, 한 곳"만 말한다. 재평가 전 연습 대화 정리를 꼭 짚는다.
2. 짝 상호평가(10분): 5분씩 역할을 바꾼다. 시간을 알려 준다.
3. 로드맵(8분): 1단계는 반드시 기관 보안 협의라고 먼저 말한다(CD-01).
4. 발표(5분): 한 사람 1~2분, 페이지의 세 가지만 말하게 한다.
5. 수료 설문(5분): 교시 안에서 응답하게 한다(CD-11). 과정 마무리 말은 설문 뒤에 한두 문장만 한다.

## 순회 지도
- **원인 분류**: 판별 질문 1번을 키트 파일로 직접 확인했는지 본다. "자료에 없음" 문항에서 "자료에 답이 없으니 근거"로 짚는 경우가 있다. 규정이 "확인 필요로 안내하라"고 정한 조문을 찾게 하면 원인이 지침임을 스스로 찾는다.
- **카드**: 직접 쓰기 단계다. 5칸 뼈대로 쓰기 어려우면 힌트 보기를 펼치게 한다. 질문과 받은 답만 넣었는지 본다(막힘 지점 sp-d2-07-a).
- **고치기**: 세 곳을 한꺼번에 고치거나 정답을 지침에 적는 수강생을 멈춘다. 고치기 전 지침이 지침 버전에 있는지 본다.
- **재평가**: D2-6과 같은 5문항, 같은 방법인지 본다. 원인을 찾던 대화를 지우지 않고 재평가하는 경우가 흔하다.
- **상호평가**: 짝이 설명 없이 보는지 본다. 설명을 시작하면 "6번(동료가 설명 없이 써볼 수 있다)을 보는 중"이라고 말해 준다.
- **로드맵**: 1단계가 보안 협의인지, 4단계에 개정 담당자와 주기가 있는지만 먼저 본다(막힘 지점 sp-d2-07-b, sp-d2-07-c). 막히면 페이지의 예상 결과 네 단계를 복사해 고치게 한다.

## 흔한 오류
| 증상 | 대응 |
|---|---|
| 0점 문항이 없다 | 6~10번 중 세 문항을 같은 방법으로 실행하게 한다. 그래도 없으면 상호평가의 "아니오" 항목 하나를 고치게 한다 |
| 원인을 근거로 짚고 키트 밖 자료를 만들어 올리려 한다 | 막는다. 가상 자료를 지어 올리지 않는다. 로드맵에 "자료 보충"으로 적고 다른 0점 문항을 고르게 한다 |
| 기대 답변과 틀린 이유를 Project 대화에 넣어 원인을 물었다 | 그 대화를 지우게 한다. 카드에는 질문과 받은 답만 넣는다(CD-17) |
| 재평가에서 방법을 바꿨다(기대 답변을 함께 넣음, Project 안 채점) | 점수를 비교할 수 없다고 말하고 D2-6과 같은 방법으로 다시 재게 한다 |
| 맞던 문항이 새로 틀렸다 | 지침 버전의 v1로 되돌리고 문장을 다르게 고치게 한다. 되돌린 것도 개정 기록에 적는다 |
| 상호평가를 위해 계정이나 Project를 넘기려 한다 | 넘기지 않는다. 화면만 보여 주고 짝이 질문 하나를 직접 해 본다 |
| 로드맵 1단계에 실제 자료 넣기를 적었다 | 보안 협의를 1단계로 옮기게 한다. 협의 전에는 실제 기관 문서·개인정보를 넣지 않는다(CD-01) |
| 개정 담당자를 "수시", "필요할 때"로 적었다 | 역할 이름과 주기(예: 매주 ○요일)로 바꾸게 한다. 점검표 12번 기준이다 |
| 수료 설문 링크가 열리지 않는다 | 강사 화면의 QR이나 종이 설문으로 대신한다 |

## 시간이 부족할 때 생략
course.yaml `skip_if_short`와 같다.
- 발표를 건너뛴다. 발표 세 가지 중 "가장 중요한 한 줄"만 로드맵 아래에 적게 한다.
- 개선·재평가, 상호평가, 로드맵, 수료 설문은 줄이지 않는다. 두 학습목표를 확인하고 수료 요건(상호평가 참여)을 채우는 활동이다.

## 과정 마무리에서 말할 것
- 6요소가 모두 있어야 하네스다. 긴 프롬프트는 하네스가 아니다.
- 실제 업무 적용은 기관 보안 협의 뒤다. 로드맵 1단계부터 시작한다.
- 설계서, 하네스 대장, 로드맵은 복귀 후에도 계속 고쳐 쓰는 문서다.
- 수료 판정 방식과 기준은 운영 기관과 협의 중이다 [TBD: OQ-19]. 수강생에게 기준 수치를 말하지 않는다.

## 강의 준비
- 카드 `card-improvement-finder`를 실제로 테스트하고 `tested_at`·`tested_by`를 채운다(prep/card-tests.md Day 2 카드 표).
- 점검표 12항목 상호평가 폼을 만들어 `form-peer-review-12`에 등록한다(prep/google-sheets-forms.md 3절). 준비 전에는 `/templates/` 점검표를 인쇄한다.
- 수료 설문 폼을 만들거나 운영 기관 설문을 받아 링크를 준비한다(prep/google-sheets-forms.md). 이메일 수집은 끈다. 설문 링크를 등록부에 올릴지 정한다.
- 하네스 대장 템플릿 시트에 "적용 로드맵" 탭(`sheet-harness-ledger`의 roadmap)을 같은 열로 만든다.
- 예시 키트 5종을 각각 한 번씩 미리 돌려, 흔히 나오는 0점 문항과 원인(각 키트 `instructor-notes.md`의 틀리기 쉬운 문항)을 확인해 둔다.
