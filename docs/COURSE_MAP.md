# COURSE_MAP — 과정 설계 근거

**COURSE_MAP = [`content/course.yaml`](../content/course.yaml)(수치·구조의 유일한 원천) + 이 문서(설계 근거).**
이 문서에는 시간·분·문항 수 같은 수치를 적지 않는다. 교시 목록, 활동 시간, 학습목표, 산출물, 카드 배치, 막힘 지점은 course.yaml을 본다.

## 1. 과정의 한 줄 흐름
업무 문제 발견 → 업무 흐름 분석 → AI와 사람의 역할 구분 → 지침 → 근거 → 도구 → 평가 기준 → 실행 → 결과 확인 → 실패 분석 → 수정 → 재실행 → 안전장치 확인 → 기록 → 실제 업무 적용

## 2. Day 1과 Day 2의 역할
| | Day 1 — 지침·근거·검증 | Day 2 — 도구·안전장치·기록 + 내 업무 |
|---|---|---|
| 질문 | "한 건을 믿을 수 있게 답하게 하려면?" | "여러 건을 흐름으로 처리하고, 안전하게 운영하고, 내 업무로 옮기려면?" |
| 사례 | 공통 예제 하나: 전입신고 민원 답변 비서 | 오전: Day 1 비서를 그대로 이어 씀 / 오후: 예시 5종 중 선택(CD-10) |
| 요소 중심 | ① 지침 ② 근거 ④ 검증 | ③ 도구 ⑤ 안전장치 ⑥ 기록 → 오후에 6요소 통합 |
| 끝났을 때 | 점수가 오른 민원 비서(개정 기록 포함) | 내 업무 하네스 설계서·Project·점수 전/후·로드맵 |

Day 2 오전은 **새 예제를 만들지 않는다.** Day 1에서 만든 민원 비서 Project를 폼·시트 흐름에 연결해 "하네스 위에서 도구를 돌린다"는 것을 보여 준다. 그래서 Day 2 오후의 설계서는 오전에 완성된 민원 하네스를 본보기로 삼을 수 있다.

## 3. 교시 간 산출물 연결
각 교시는 다음 교시가 쓰는 산출물을 만든다. course.yaml `outputs[].used_by`가 이 연결을 기록하고 validator(V-CRS-005)가 검사한다.
- Day 1: 기준 답(임시 채팅) → 지침 v1 → Project v1과 전/후 비교 → Project v2(근거) → 평가세트 → 점수표 → Project v3와 점수 전/후
- Day 2: 공용 응답 시트 → 분류 대장 → 초안과 검토 기록 → 민원 하네스 완성본과 로그 대장 → 설계서와 평가 문항 → 내 Project와 1차 점수 → 점수 전/후와 로드맵

## 4. 교시 안의 흐름
모든 교시는 가능한 한 **개념 → 시연 → 따라하기 → 실습 → 검증 → 개선** 순서를 따른다. course.yaml `activities[].kind`(explain/demo/follow/practice/check/reflect)가 이 순서를 나타낸다. 설명(explain)은 짧게, 실습(practice/follow)은 반드시 포함한다(V-CRS-004).

## 5. 시간 설계 원칙 (CD-03, CD-11)
- 교시는 50분이며, 핵심 활동은 constraints의 상한 이하로 잡고 나머지는 버퍼·전환으로 둔다(V-CRS-003).
- 초보자가 있으므로 넘치는 내용은 "더 해보기"로 빼고, 교시마다 `skip_if_short`(시간 부족 시 생략)를 둔다.
- 입과 안내(D1-1)와 수료 설문(D2-7)은 교시 안에 포함한다.

## 6. 6요소 배치 근거
- ①②④는 Day 1에서 "한 건의 품질"로, ③⑤⑥은 Day 2에서 "흐름과 운영"으로 먼저 다룬다.
- ⑤ 안전장치는 Day 1 근거 교시(출처 없는 답 방지)와 평가세트(금지·개인정보 문항)에서 미리 등장하고, Day 2 4교시에서 점검 실습으로 종합한다. 붙여넣기(첨부) 전 개인정보 점검은 처음 데이터를 넣는 D2-2에서 먼저 한다.
- ⑥ 기록은 D1-2부터 하네스 대장에 쌓아, Day 2에서 로그 대장 운영 규칙으로 확장한다.
- 요소별 최소 교시 수는 constraints에 있고 validator(V-CRS-006)가 검사한다. 요소 정의는 [HARNESS_ELEMENTS.md](HARNESS_ELEMENTS.md).

## 7. 교과목 7개와의 대응
제안서 양식의 교과목 7개는 course.yaml `subjects`와 각 교시의 `subject`로 연결한다. 제안서 개정본(CD-08)은 이 대응을 사용한다.

## 8. 제안서 대비 주요 변경
PDF 원안과 달라진 점은 모두 [ADR.md](ADR.md)의 CD 항목에 "PDF 원문"과 함께 기록한다(CD-01, 03, 06, 07, 09, 10, 16~20).
