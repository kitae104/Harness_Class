# 실습 설계 원칙

모든 실습 콘텐츠가 따르는 설계 원칙이다. 교시별 적용(막힘 지점, 지원 방식, 카드)은 course.yaml `stuck_points`와 `cards`에 기록한다.

## 1. 실습 3단 구조
| 단계 | 수강생이 하는 일 | 콘텐츠 |
|---|---|---|
| STEP A 함께 하기 | 강사 화면을 보며 같은 것을 따라 한다 | 강사 시연 순서, 필수 경로 3~5단계 |
| STEP B AI 도움받기 | 막히는 곳에서 카드를 쓴다 | AI에게 도움받기 카드(막힘 지점에만) |
| STEP C 내 업무 적용 | 자기 업무(또는 예시 키트)로 바꿔 본다 | 바꿀 곳 안내, 예시 입력 |

- Day 1의 STEP C는 "내 업무 후보 메모" 정도로 가볍게 한다. 본격 적용은 Day 2 오후.
- 빈 화면에서 처음부터 쓰게 하지 않는다. 항상 틀·예시·결함 있는 초안 중 하나를 준다.

## 2. 전/후 비교
주요 실습에는 "첫 번째 결과"와 "하네스를 개선한 뒤의 결과"를 비교하는 경험을 넣는다.
- 지침 수정 전 원문을 하네스 대장 "지침 버전" 탭에 복사한 뒤 수정한다(프로젝트 복제 기능은 확인 전 [TBD: OQ-02]).
- D1-1 기준 답변은 **비개인화 임시 채팅**에서 받는다. 개인 메모리·맞춤 지침의 영향을 없애기 위해서다 [AS-OF: chatgpt-temporary-chat].

## 3. 평가와 개선 루프
- **평가세트 먼저**: 만들기 전에 무엇을 맞혀야 하는지부터 정한다(D1-5, D2-5).
- **채점(CD-06)**: 문항당 1점. 정확과 출처를 모두 충족해야 1점, 금지 위반은 0점. "자료에 없음" 문항은 "확인 필요"로 답하면 1점(출처 요건 면제). 채점표 열: 번호 / 질문 / 답변 요약 / 정확 / 출처 / 금지 / 점수 / 틀린 이유.
- **실행(CD-17)**: 평가 문항을 두 번에 나눠 새 대화에서 실행하고, 사람이 3문항 표본을 확인한다. 같은 프로젝트 안의 다른 대화가 결과에 영향을 줄 수 있으므로 연습 대화와 평가 대화를 구분한다 [AS-OF: chatgpt-project-memory] [TBD: OQ-03].
- **실패 원인 3분류**(원인 판별 질문):
  1. 올린 자료에 답이 있는가? 없다 → **근거** 문제
  2. 지침에 그 상황의 규칙이 있는가? 없다 → **지침** 문제
  3. 금지사항을 어겼는가? 어겼다 → **금지 위반**(지침의 금지사항 강화)
- **재평가**: 실패 문항 + 무작위 5문항(다른 문항도 망가지지 않았는지 확인).
- **자기채점의 한계**: AI가 자기 답을 관대하게 채점하는 예를 "잘못된 결과 예시"로 보여 준다.

## 4. 지원 방식 9종과 선택 기준
| 번호 | 지원 방식 | 이럴 때 쓴다 |
|---|---|---|
| 1 | 복붙 카드(따라 쓰기) | 처음 하는 절차, 반복 실행 도구(채점 등) |
| 2 | 대괄호 수정 카드(바꿔 쓰기) | 같은 기술의 두 번째 경험, 내 업무로 바꿀 때 |
| 3 | 예시 입력 | 무엇을 넣어야 할지 모를 때(질문 예시, 역할카드) |
| 4 | 예상 결과 | 결과가 맞는지 판단 기준이 필요할 때 |
| 5 | 잘못된 결과 예시 | 그럴듯하지만 틀린 결과를 알아봐야 할 때(지어낸 조문, 관대한 채점, 금액 단정) |
| 6 | "AI에게 이렇게 물어보세요" | 막혔을 때 스스로 질문하는 법을 익힐 때 |
| 7 | 강사 시연 | 메뉴 위치, 처음 보는 화면 |
| 8 | 문제 해결 카드 | 출력 끊김, 표 깨짐, 결과 이상(공통 3종) |
| 9 | 체크리스트 | 설정·검토처럼 빠뜨리기 쉬운 항목 |

규칙:
- **카드는 막힘 지점이 있는 곳에만** 만든다. course.yaml에서 카드는 반드시 어떤 `stuck_points[].card`의 근거를 가져야 한다(V-CRS-008).
- 실습형 교시는 예상 결과(4)와 잘못된 결과 예시(5)를 반드시 포함한다(V-CRS-010).
- 교시당 카드는 2장 이하를 권장한다(V-CRS-011 경고).

## 5. 기술별 단계 이동 (따라 쓰기 → 바꿔 쓰기 → 직접 쓰기)
단계는 **시간표 순서가 아니라 기술별 반복 횟수**로 올린다. 직접 쓰기(L3)는 같은 기술을 두 번 경험한 뒤에만 쓴다.
| 기술 | 1회차 | 2회차 | 3회차 |
|---|---|---|---|
| 지침 쓰기 | D1-2 따라 쓰기(결함 초안 진단 + 비판 카드) | D2-4 바꿔 쓰기(규칙 문장 추가) | D2-6 직접 쓰기 |
| 근거 연결 | D1-4 바꿔 쓰기 | D2-6 바꿔 쓰기~직접 쓰기 | — |
| 평가 문항 | D1-5 바꿔 쓰기 | D2-5 바꿔 쓰기 | — |
| 채점 실행 | D1-6 따라 쓰기 | D2-6 따라 쓰기(같은 카드) | — |
| 실패 분석 | D1-7 바꿔 쓰기 | D2-4 바꿔 쓰기 | D2-7 직접 쓰기 |
| 업무 분석 | D1-2 강사 시연 | D2-5 바꿔 쓰기 | 로드맵(실제 업무) |

카드 한 장에 세 단계를 겹쳐 담는다(구조 → 힌트 → 전체). 기본으로 보이는 단계는 교시의 단계이고, 막힌 수강생은 펼쳐서 더 많은 도움을 받는다.

## 6. "왜 이런 지시가 필요한가"를 이해시키는 장치 4종
1. **5칸 뼈대와 문장별 해설**: 모든 카드는 역할 / 입력 / 규칙 / 출력 형식 / 모를 때 — 지침서 5항목과 같은 구조로 쓰고, 문장마다 요소 배지와 한 줄 이유를 붙인다.
2. **빼보기 실험**(D1-3 버퍼, D1-7 선택): 지침에서 한 줄을 지우고 같은 질문을 다시 해서 차이를 본다.
3. **카드를 지침으로 옮기기**(D2-2 끝~D2-3 시작): 매번 붙이던 분류 규칙을 Project 지침으로 옮기면 카드가 짧아진다 — "긴 프롬프트 ≠ 하네스" 체험.
4. **한 문장 되돌아보기**: 카드를 쓴 뒤 "가장 중요한 한 줄과 그 이유"를 하네스 대장에 한 문장으로 적는다.

## 7. AI를 설계 파트너로 쓰기
AI를 답안 생성기가 아니라 **설계 파트너**로 쓴다. 카드의 기본 패턴은 "먼저 스스로 쓰고, AI에게 빠진 것과 애매한 것을 비판받기"다. 수강생이 스스로 쓸 수 있는 질문 예:
- 내가 지금 무엇을 빠뜨렸는지 확인해 줘
- 이 지침에서 애매한 부분을 찾아 줘
- 이 업무에서 AI가 하면 안 되는 일을 찾아 줘
- 이 답변이 틀린 원인이 지침인지 근거인지 분석해 줘

## 8. 데이터와 안전
- 실습 데이터는 가상 자료와 공개 법령만 쓴다. 실제 기관 문서는 로드맵의 "기관 보안 협의 후" 단계에서만 다룬다(CD-01).
- 입력 데이터를 넣기 전(D2-2)에 개인정보 점검을 먼저 한다.
- 모든 AI 결과물에는 "초안·검토 필요" 표시를 요구하고, 발송·판단은 사람이 한다.

## 9. AI 왕복 활동 시간 기준
AI에게 여러 번 묻는 활동은 분 배분이 비현실적이 되기 쉽다. 초보자 기준으로 설계한다.
- AI 질문 1회(붙여 넣기 → 답 읽기 → 기록)에 최소 2분을 잡는다.
- 활동 분(course.yaml `activities[].minutes`)은 "질문 수 × 2분 + 비교·정리 시간" 이상으로 설계한다.
- 기록 항목은 판단 하나(예/아니오 등)와 붙여 넣기로 줄인다. 자유 서술 기록은 시간을 가장 많이 잡아먹는다.
