# 학습목표 작성 기준

교시별 학습목표의 **내용**은 [`content/course.yaml`](../content/course.yaml) `lessons[].objectives`에만 적는다. 이 문서는 과정 수준의 목표, 목표 작성 규칙, 수료 기준의 의미를 정의한다.

## 1. 과정 목표
과정을 마친 수강생은 자신의 업무를 AI가 반복해서 수행하도록 **지침·근거·도구·검증·안전장치·기록**으로 업무 환경을 설계할 수 있다.

이를 다섯 가지 역량으로 나눈다. course.yaml `completion.self_check` 5문항이 이 역량을 사전·사후로 묻는다.
| 역량 | 이런 행동으로 드러난다 |
|---|---|
| 구분 | 프롬프트·컨텍스트·하네스의 차이를 내 업무 예로 설명한다. "긴 프롬프트 = 하네스"라고 말하지 않는다 |
| 지침 설계 | 지침서 5항목을 구체적으로 쓴다 |
| 원인 분석 | 틀린 답의 원인을 지침·근거·금지 위반으로 나눈다 |
| 검증 | 평가 문항과 채점 기준을 만들고 점수로 개선을 보인다 |
| 안전한 운영 | AI에게 맡기면 안 되는 일, 사람이 검토할 지점, 기록할 항목을 정한다 |

## 2. 학습목표 작성 규칙
1. **관찰 가능한 동사**로 끝낸다: 작성한다, 구분한다, 비교한다, 설명한다, 기록한다, 실행한다. "이해한다", "안다"는 쓰지 않는다(validator 경고 대상, Phase 1에서 추가).
2. 목표 하나는 **산출물 하나 이상**을 가리킨다(`objectives[].outputs`). 산출물이 없는 목표는 확인할 수 없다(V-CRS-005).
3. 교시당 목표는 2~3개. 50분 안에 확인할 수 있는 분량이어야 한다.
4. 목표 문장에 도구 사용법만 쓰지 않는다. "Project를 만든다"가 아니라 "지침을 Project에 넣어 매번 같은 규칙으로 답하게 만든다"처럼 **하네스 관점의 이유**를 담는다.
5. core 교시의 목표에 Codex나 선택 심화 내용을 넣지 않는다(V-CRS-009).

## 3. 결과 확인(checks) 작성 규칙
- 결과 확인은 `{id, text}` 형식으로 쓰고(`lessons[].checks`), 학습목표마다 그 목표를 확인하는 결과 확인 ID 목록을 `objectives[].checks`로 연결한다.
- **학습목표마다 결과 확인이 1개 이상** 있다. 결과 확인이 없는 목표는 달성 여부를 알 수 없다(V-LSN-005). 산출물 연결(V-CRS-005)만으로는 목표 달성을 확인한 것이 아니다.
- 목표가 달성됐는지 **수강생 스스로** 확인할 수 있는 관찰 가능한 문장으로 쓴다. 예: "5항목이 모두 채워져 있다", "자료 밖 질문 2개에 '확인 필요'로 답한다".
- 교시마다 최소 1개(V-CRS-004).

## 4. 수료 기준
course.yaml `completion`에 정의한다.
- 필수 산출물: 설계서, Project 2개, 점수 전/후, 로그 대장, 로드맵
- 선택 산출물: 업무용 폼(CD-09)
- 참여: 12항목 짝 상호평가
- 수료 판정 방식(강사 확인, 자가 체크 등)과 기준 수치는 운영 기관과 협의한다 [TBD: OQ-19].

## 5. 난이도 흐름
초급 → 중급. 같은 기술을 반복할수록 도움을 줄인다(기술별 단계 이동은 [PRACTICE_DESIGN.md](PRACTICE_DESIGN.md)). Day 2 오후는 새 업무를 다루므로 난이도가 높아지는 만큼 예시 설계서와 키트로 받친다.
