# 콘텐츠 작성 가이드

모든 교시·모듈·안내 페이지가 따르는 규칙이다. 이 문서는 모든 step에 주입되는 core 문서다.

## 1. 교시 유형과 템플릿
course.yaml `type`에 따라 템플릿을 고른다. 13섹션을 모든 교시에 강제하지 않는다.

**공통 필수 섹션**(모든 유형): 이번 시간에 할 일 · 학습목표(course.yaml에서 자동) · 필수 경로(3~5단계) · 실습 · 결과 확인(course.yaml `checks`) · Harness에서 무엇을 바꿨는가 · 다음 교시 연결

| 유형 | 추가 섹션 | 비고 |
|---|---|---|
| 개념형(concept) | 왜 필요한가, 핵심 개념, 체험 | 설명은 짧게, 체험 활동 필수 |
| 실습형(practice) | 강사 시연, 함께 따라하기, AI 도움받기, **예상 결과, 잘못된 결과 예시**, 잘 안 될 때 | 예상 결과와 잘못된 결과 예시 필수(V-CRS-010) |
| 프로젝트형(project) | 예시 선택 안내, 설계 예시(민원 완성본), 점검표 | 강사 시연 최소, 순회 지도 |

- "필수 경로"는 페이지 맨 위에 둔다. 개념 설명·잘 안 될 때·결과 예시는 접이식으로 둔다(수업 중 지금 할 일을 바로 찾게).
- 강사 안내(소요시간, 시연 순서, 흔한 오류, 생략 항목)는 페이지 하단 접이식. 민감 메모는 쓰지 않는다(CD-02).

## 2. 기준 예시 (반드시 참조)
유형마다 사람이 승인(reviewed)한 기준 예시 교시가 있다. 같은 유형의 교시를 쓸 때는 기준 예시를 먼저 읽고 구조·분량·어조를 맞춘다.
| 유형 | 기준 예시 | 만드는 시점 |
|---|---|---|
| 개념형 | D1-1 `d1-harness-intro` | Phase 1 |
| 실습형 | D1-4 `d1-context` | Phase 3 첫 step |
| 프로젝트형 | D2-5 `d2-project-design` | Phase 5 첫 step |

기준 예시가 reviewed가 되기 전에는 같은 유형의 다른 교시를 만들지 않는다.

## 3. 문체와 분량
- 강의체 "~합니다". 공문체("~함", "~할 것")는 쓰지 않는다.
- 한 문장은 60자 안팎, 한 문단은 3문장 이내. 섹션마다 핵심 한 줄을 먼저 쓴다.
- 섹션 분량: 개념 설명은 화면 한 장, 실습 단계는 번호 목록으로 한 단계에 한 동작.
- 초보자 기준으로 쓴다. 메뉴 이름은 화면에 보이는 그대로 쓰되 `<Feature>`로 감싼다.

## 4. 용어
- 한국어를 먼저 쓰고 처음 나올 때 영문을 병기한다: 기록(Observability).
- 수강생 화면 용어는 [`content/glossary.yaml`](../content/glossary.yaml)의 `student_label`을 쓴다: 따라 쓰기 / 바꿔 쓰기 / 직접 쓰기, AI에게 도움받기, 필수 / 선택, 숨은 지시문, 표 파일(CSV).
- 금지 표현은 [`content/banned-terms.yaml`](../content/banned-terms.yaml). 수강생 콘텐츠에서 검출되면 오류(V-TXT-001).

## 5. 수치·제품·출처는 직접 쓰지 않는다
| 종류 | 본문에서 쓰는 방법 |
|---|---|
| 시간, 교시, 목표, 산출물 | course.yaml에서 자동 표시 |
| 제품 기능, 한도, 메뉴 위치, 모델명 | `<Feature id="..."/>` |
| 법령 조문, 공식 문서 | `<Source id="..." article="..."/>` |
| 구글 시트·폼 링크 | `<ExternalLink id="..."/>` |
| 확인되지 않은 내용 | `[TBD: OQ-xx]`로 표시하고 OPEN_QUESTIONS에 등록 |

## 6. 예시와 가상 자료
- 예시 입력·예상 결과·잘못된 결과 예시는 실제 화면처럼 보이되 가상 자료로 만든다. 첫머리에 "교육용 가상 자료"를 밝힌다.
- 이름은 명백한 가상 이름, 전화번호는 `010-0000-XXXX`만(V-PII-001).
- 잘못된 결과 예시에는 **어디가 왜 틀렸는지**를 바로 아래에 적는다.

## 7. 핵심 메시지 지키기
- "긴 프롬프트 = 하네스"로 읽힐 문장을 쓰지 않는다. 카드가 길어지면 반복되는 지시를 지침으로 옮기라고 안내한다.
- 기능 사용법보다 "AI가 안정적으로 일하는 환경을 설계하는 법"을 앞에 둔다. 도구 절차는 이유를 한 줄 붙인 뒤에 쓴다.
- Codex는 core 교시에 등장시키지 않는다(V-CRS-009). 선택 심화 링크만 둔다.

## 8. 작성 순서
1. course.yaml의 해당 교시(목표·산출물·막힘 지점·카드)가 먼저 정해져 있어야 한다.
2. 기준 예시를 읽는다.
3. 필수 경로 → 실습 → 결과 확인 → 나머지 섹션 순으로 쓴다.
4. course.yaml에서 자기 교시(와 그 교시의 카드)의 status만 `draft`로 바꾸고, `npm run verify -- --scope lesson:<id>`로 검사한다. reviewed로 올리지 않는다(ADR-011).
