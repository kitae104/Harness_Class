# Harness 6요소

과정 전체가 쓰는 6요소의 정의, 요소를 "담는 곳", 완성 기준을 정의한다. 요소가 어느 교시에서 다뤄지는지는 course.yaml `lessons[].elements`.

## 1. Prompt → Context → Harness
| 단계 | 무엇을 다루나 | 공무원 업무로 바꾸면 | 한계 |
|---|---|---|---|
| 프롬프트 엔지니어링 | 질문 한 번을 잘 쓰는 법 | "민원 답변 초안 써줘" | 사람마다, 날마다 결과가 다르다 |
| 컨텍스트 엔지니어링 | 무엇을 함께 보여 줄지 | 규정·매뉴얼·지난 답변 첨부 | 근거는 있지만 검증·안전장치가 없다 |
| 하네스 엔지니어링 | AI가 일하는 틀 전체 | 지침 + 근거 + 도구 + 평가세트 + 안전장치 + 기록 | 누가 써도 같은 품질, 틀리면 고칠 수 있다 |

**가르칠 때 반드시 막을 오해: "긴 프롬프트 = 하네스".** 하네스는 프롬프트 길이가 아니라 업무 환경이다. 반복되는 지시는 Project 지침으로 옮기고(D2-2 "카드를 지침으로 옮기기"), 평가와 기록이 없으면 하네스가 아니다.

## 2. 요소 정의 (제안서 원문 + 사용자 확장)
| 요소 | 무엇 | 수업에서 만드는 것 |
|---|---|---|
| ① 지침 Instructions | 역할, 업무 범위, 금지사항, 출력 형식, 모를 때 행동 | 업무 지침서 5항목 |
| ② 근거 Context | 규정, 편람, FAQ, 업무 매뉴얼, 기존·기준 자료, 출처 | 자료 목록(기준일), 출처(조문) 규칙 |
| ③ 도구 Tools | 입력을 모으고(폼) 쌓고(시트) 여러 건을 처리하는(ChatGPT) 흐름. Codex는 선택 확장 | 업무용 폼(선택), 분류 대장 |
| ④ 검증 Evals | 평가 질문, 기대 결과, 채점 기준, 점수, 실패 원인, 수정, 재평가 | 평가세트, 점수표 전/후 |
| ⑤ 안전장치 Guardrails | 개인정보 최소 수집·마스킹, 근거 없는 답변 방지, 범위 밖 판단 방지, "초안" 표시, 사람의 최종 검토, 기관별 보안정책 확인 | 안전장치 체크리스트, 금지사항 |
| ⑥ 기록 Observability | 질문, 답변, 사용 근거, 결과, 오류, 검토자, 수정 내용, 버전, 개정 이유 | 하네스 대장(지침 버전·자료 목록·평가·로그 탭) |

## 3. 요소와 "담는 곳"은 다르다
ChatGPT Project는 하나의 요소가 아니라 **①과 ②를 담는 그릇**이다. 수강생이 "도구 = ChatGPT"로 오해하지 않게 구분한다.
| 요소 | 담는 곳 |
|---|---|
| ① 지침 | Project 지침란 |
| ② 근거 | Project 파일 (입력 데이터가 아님) |
| ③ 도구 | 구글 폼(입력) → 구글 시트(축적) → 채팅 첨부로 여러 건 처리 → 시트(대장) |
| ④ 검증 | 하네스 대장 평가 탭 + 새 대화에서 실행하는 채점 카드 |
| ⑤ 안전장치 | 지침의 금지사항, 폼 설정, 데이터 제어 설정, 사람 검토 열, 기관 보안 협의 |
| ⑥ 기록 | 하네스 대장 지침 버전·로그 탭 |

## 4. 완성 기준 — 점검표 12항목 (제안서 원문)
D2-7 짝 상호평가와 설계서 검토에 같은 기준을 쓴다.
| 요소 | 점검 항목 |
|---|---|
| ① 지침 | 1. 역할·범위가 한 문장으로 적혀 있다 / 2. "모를 때 행동"이 적혀 있다 |
| ② 근거 | 3. 등록 자료 목록과 기준일자가 있다 / 4. 출처 없는 답을 막는 규칙이 있다 |
| ③ 도구 | 5. AI가 하는 일과 하지 않는 일이 구분된다 / 6. 동료가 설명 없이 써볼 수 있다 |
| ④ 검증 | 7. 평가세트가 10문항 이상이다 / 8. 현재 점수와 목표 점수가 있다 |
| ⑤ 안전장치 | 9. 개인정보 처리 규칙이 있다 / 10. 발송·공개 전 사람이 확인하는 단계가 있다 |
| ⑥ 기록 | 11. 질문·답변·출처가 기록된다 / 12. 개정 담당자와 주기가 있다 |

## 5. 행정 관행으로 설명하기
공무원에게 익숙한 절차에 빗대어 요소를 설명한다.
| 행정 관행 | 하네스 요소 |
|---|---|
| 결재 — 기안자가 초안을 쓰고 결재권자가 확정한다 | ⑤ AI는 초안만, 발송·판단은 사람 |
| 규정 인용 — 답변에 근거 조문을 적는다 | ② 출처 표시, 자료에 없으면 "확인 필요" |
| 기록 보존 — 문서 대장과 처리 이력을 남긴다 | ⑥ 로그 대장, 개정 기록 |
| 업무 편람 개정 — 문제가 생기면 편람을 고친다 | ④ 실패 분석 → 지침·근거 수정 → 재평가 |
