# 실습 사례 명세

수업에서 쓰는 사례의 **명세**다. 사례의 실제 자료(법령 발췌, FAQ, 가상 데이터, 평가 문항)는 Phase 2·4에서 `content/kits/<kit-id>/`에 만들고, 이 문서는 무엇을 담아야 하는지만 정한다. 법령 조문과 시행일은 [`content/sources.yaml`](../content/sources.yaml)에만 적는다.

## 1. 키트 공통 구성 (kit.yaml 필수 항목, Phase 2에서 validator 규칙 추가)
| 항목 | 내용 |
|---|---|
| `id`, `title`, `track` | 키트 ID, 제목, core/optional |
| `sources` | 근거로 쓰는 sources.yaml ID(법령 조문 단위) 또는 `fictional` 자료 |
| `guideline_frame` | 지침서 5항목 틀(Day 1 공통 키트는 v0 결함 지침 포함) |
| `context_files` | Project에 올릴 근거 자료(법령 발췌, 교육용 FAQ) |
| `input_data` | 채팅에 첨부할 가상 입력 데이터(CSV) |
| `eval_candidates` | 평가 문항 후보와 기대 답변(핵심 포인트 2개 + 근거) |
| `form_template` | 업무용 폼 문항(선택 산출물용) |
| `privacy_notes` | 이 키트에서 특히 주의할 개인정보·보안 사항 |
| `fictional_label` | 가상 자료임을 알리는 문구 |

## 2. Day 1 공통 키트 — 전입신고 민원 답변 비서 (`day1-civil`)
- **근거**: 주민등록법·시행령의 전입신고 관련 조문(`law-resident-registration`, `law-resident-registration-decree`). 구청 편람은 복제하지 않고 "법령 기반 교육용 FAQ"로 만든다(CD-04).
- **지침서 5항목 작성 예(제안서 원문)**:
  - 역할: ○○구 전입·전출 담당 안내 직원. 존댓말, 핵심부터 3문장 이내
  - 범위: 주민등록법·시행령과 교육용 FAQ 범위의 절차·서류·기한 안내
  - 금지사항: 개인정보 요청·저장 금지, 과태료 액수 단정 금지, 근거 없는 추측 금지
  - 출력 형식: [답변] → [필요 서류] → [근거: 조문] → [담당 연락처]
  - 모를 때 행동: "확인이 필요합니다" + 담당 연락처 안내, 지어내지 않음
- **v0 지침(D1-2 개선 연습용)**: 위 5항목 중 일부가 추상적이거나 비어 있는 초안. 수강생은 이것을 v1로 고친다.
- **의도된 결함(CD-18)**: 수강생이 작성하지 않는 자료에만 둔다.
  1. 교육용 FAQ에서 항목 1개를 누락한다 → 관련 문항이 D1-6에서 틀리고, D1-7에서 근거를 보강하면 맞는다.
  2. 전입과 전출을 혼동하게 만드는 범위 애매 문항을 넣는다 → 지침의 범위 문장을 고치면 맞는다.
  수강생에게 "일부러 단순하게 만든 초안"임을 공개한다.
- **평가세트 20문항 구성**: 정상 12 / 자료에 없음 4 / 금지·개인정보 요구 2 / 유도·숨은 지시문 2. 기대 답변은 핵심 포인트 2개 + 근거 조문. 채점은 CD-06(문항당 1점).
- **과태료 금액**: 수업 자료에서 금액을 단정하지 않는다. 시행령 [별표 4] 금액은 아직 원문 확인 전이다 [TBD: OQ-07]. 금지사항 "과태료 액수 단정 금지"의 평가 문항으로 활용한다.

## 3. Day 2 오전 사례 — 민원 접수 흐름 (Day 1 키트 확장)
- **폼**: 민원 접수 폼(기본 경로). 문항 4~6개: 접수일 / 민원 유형(객관식) / 내용(장문) / 희망 회신 방법 / 연락처(선택). 이메일 수집 끔.
- **데이터(CD-19)**: 강사 공용 폼에 수강생이 역할카드를 보고 3건씩 응답 + 부족 시 제공 CSV(가상 민원 30건). 역할카드와 CSV는 가상 이름과 `010-0000-XXXX` 번호만 쓴다.
- **분류 기준표**: 제안서 프롬프트 ①의 "[유형·부서 기준 붙여넣기]"에 들어갈 표. 유형, 긴급도(높음·보통·낮음), 담당 부서, "확인 필요" 판단 기준.
- **공격성 입력 2건(D2-4)**: 개인정보를 요구하는 민원, 본문에 숨은 지시문이 들어 있는 민원.
- 변형 예제(현장 점검, 수요조사)는 STEP C로만 제공한다.

## 4. Day 2 오후 — 예시 5종 키트 (CD-10)
| 키트 ID | 업무 | 근거 | 특이사항 |
|---|---|---|---|
| `rule-qa` | 규정 Q&A 비서(인사·복무) | 국가공무원 복무규정 1종(`law-civil-service-conduct`) [PROVISIONAL] | 국가직·지방직으로 나누지 않는다(CD-12). 평가 문항은 두 직군 공통 주제(근무시간·연가·병가) 중심. 지방직·기관별 세부 질문은 "소속 기관 규정 확인 필요"가 정답인 문항으로 넣는다 |
| `civil-draft` | 민원 답변 초안 비서 | 실제 법령(Day 1과 다른 민원 유형) [TBD: OQ-20] | Day 1과 같은 유형이면 안 된다 |
| `field-inspection` | 현장 점검 보고 폼 + 정리 비서 | 재난 및 안전관리 기본법 안전점검 조문(`law-disaster-safety`) [PROVISIONAL] | 제안서 폼의 "사진 올리기" 문항은 응답자 구글 로그인과 드라이브 저장이 필요하다. 사람 얼굴·차량 번호·주소가 찍히지 않게 안내하고, 기본 키트에서는 사진 문항을 선택으로 둔다 |
| `demand-survey` | 교육·행사 수요조사 + 결과 보고서 | 교육용 가상 양식(기관 내부 기준 역할) | 법령 근거 없음. "가상 자료" 표기 |
| `meeting-minutes` | 회의록 정리 비서 | 교육용 가상 회의록 양식 | 실제 회의 녹취·참석자 이름 사용 금지 |

## 5. 사례 공통 금지사항
- 실제 기관 문서, 실제 민원, 실제 인물 이름 사용 금지.
- 법령 조문은 원문을 옮길 때 sources.yaml의 시행일 버전과 대조한다. 개정되면 개설 전 재확인(`--pre-launch`).
- 가상 자료 첫머리에 "이 자료는 교육용 가상 자료이며 실제 인물·기관과 무관합니다"를 넣는다.
